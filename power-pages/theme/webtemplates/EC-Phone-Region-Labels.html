{% comment %} EC-Phone-Region-Labels (global, reusable - included once from EC-Scripts-Base) Region-aware telephone / postal / province handling for EVERY PP & EDA form on the site, driven by the COUNTRY value the Google address autocomplete writes (ISO-2 short_name, e.g. "US" / "CA"). No per-form code: * TELEPHONE fields (NOT extension fields): validated with the approved North-American (NANP) pattern when the governing country is US/CA (or any NANP country); a non-NANP country falls back to E.164 (7-15 digits, optional +). A field with no country chosen yet accepts either, so nobody is blocked. Extension fields are left alone. * The telephone label gets a format hint matching the region (NA sample vs international). * POSTAL fields: US -> label becomes "ZIP code" + ZIP validation/hint; CA (or other) keeps the original server label + A1A 1A1. * PROVINCE/TERRITORY fields: US -> label becomes "State"; CA keeps the original label. Runs on the main page AND inside modal form iframes (tagged data-ecw-modal, injected by EC-Scripts-Base) so subgrid appointee/address forms get the same behaviour. The wizard's own client validation (EC-Wizard-Tiles-Scripts) delegates its phone/postal rule to the window.ecwPhoneValid / window.ecwPostalValid helpers defined here. ZIP/State strings come from bilingual content snippets so FR pages read "Code ZIP" / "État". {% endcomment %}
